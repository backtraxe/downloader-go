# 对话命令指定相册 Caption 位置设计

日期：2026-11-22

## 目标

用户只能在 Telegram 对话框中操作。允许单次命令指定 caption 放在每组第几张
图片下，解决删除第一张图片时 caption 一并消失的问题，同时不改长期配置。

## 已选方式与备选方案

- **对话命令、单次生效（已选择）**：新增 `/caption N <链接>`，并扩展现有
  `/force` 为 `/force N <链接>`。不保存聊天状态，不读写额外配置文件。
- `config.json` 持久配置（不采用）：用户无法直接操作配置文件。
- 独立文本或回复消息（不采用）：caption 与图片分离，多组时关联不直观。
- 每张图片重复 caption（不采用）：会产生大量重复文本。

## 命令与兼容性

```text
/caption 2 <链接>
/force 2 <链接>
/force <链接>
```

- `/caption` 按普通下载处理；带位置的 `/force` 强制重新下载。
- 不带位置的 `/force` 和普通链接继续使用第一张，保持兼容。
- `N` 按十进制整数解析；缺少位置、位置不是整数或缺少链接时返回用法提示，
  不触发下载。`/force` 后不是整数的旧参数仍按链接处理。

## 分组规则

- `N <= 0` 时按 `1` 处理。
- 每个相册分组都以同一个 `N` 计算位置，不因前一组消耗了图片而递减。
- `N > len(group)` 时选择本组最后一项。
- 例如 `N=5`，拆成 10 项与 2 项的两组，caption 分别在第 5 项和第 2 项。
- 单项 `sendPhoto`/`sendVideo`、图片处理失败后的逐项重发，以及 document
  的现有 caption 语义不变；位置计算同样钳制在本组内。
- caption 仍依附于所选媒体，删除该项仍会删除 caption，本功能不承诺独立保留。

参数只在一次 bot 请求的文件上传过程中传递，不进入持久下载元数据，也不影响
下一次请求、CLI upload 或其他聊天。

- 验证 `N<=0`、指定中间项、超过组大小及多组重复使用。
- 验证图片处理失败后的逐项重发仍使用同一位置。
- 更新 bot 帮助和 Go 重写设计文档。
- 运行 `CGO_ENABLED=0 go test ./...`、`CGO_ENABLED=0 go vet ./...`、
