# 通用页面 DOM 作者提取设计

日期：2026-11-16

## 目标

通用后端能从酷安动态页的 `.username-item` 中提取作者，例如样例页面应得到
`忘记密码是啥了`，避免只生成站点目录而没有作者目录。

## 范围与约束

- 只增加作者元数据提取，不改变媒体筛选、下载、标题清理或输出布局规则。
- 不执行页面脚本；测试使用脱敏的最小 HTML 与 `httptest.Server`，全程离线。
- 不拼接 `.username-item` 的全部段落，避免把发布时间、设备名误并入作者。

## 方案比较

1. **受限 DOM 提取（已选择）**：读取 `.username-item` 首个段落，结构明确，
   不误判普通标题中的“来自”。代价是新增一条具体 CSS 选择器规则。
2. **放宽标题规则**：直接支持任意“来自 作者 - 站点”，改动较小，但更容易
   把正文中的“来自”当成作者分隔符，因此不采用。

## 实现口径

作者提取保持以下优先级：

1. 现有内联 `infotpc` 的 `name`；
2. 第一个 `.username-item` 中第一个 `p` 的文本，去除首尾空白；
3. 现有标题中的“正文 来自 作者”规则；
4. 都没有时返回空字符串。

新增独立的 DOM 提取函数，`nil` 文档或无匹配时返回空字符串。下载主链路仅在
前一种来源为空时尝试下一种，保持现有行为兼容。

## 验证

- 单元测试覆盖酷安结构、第二段落不得混入、无匹配和 `nil` 文档。
- 下载链路测试验证 `Post.Author` 使用 DOM 作者。
- 现有 `infotpc` 与标题回退测试继续通过。
- 运行 `CGO_ENABLED=0 go test ./...`、`CGO_ENABLED=0 go vet ./...`。
- 同步更新 Go 重写设计文档中的通用页面作者提取说明。
